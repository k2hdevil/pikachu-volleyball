# 개발 표준

## 의존성 관리
- 모든 라이브러리와 의존성의 최신 안정 버전 사용
- 의존성 추가 전 Context7 MCP 서버를 활용하여 호환성 확인
- 각 새로운 의존성에 대해 명확한 비즈니스 또는 기술적 가치로 정당화
- 활발한 커뮤니티가 있는 잘 관리되는 라이브러리 선호
- 프로젝트 파일에 버전 제약 조건 문서화
- 사용하지 않는 의존성 정기적으로 제거
- 환경 간 일관된 설치를 위해 lock 파일 사용

## 코드 품질 표준
- `_fixed`, `_clean`, `_backup` 등의 접미사가 붙은 중복 파일 절대 생성 금지
- 기존 파일에서 반복적으로 작업 (훅이 커밋을 자동으로 처리)
- 코드 주석에 관련 문서 링크 포함
- 언어별 컨벤션 준수 (CDK는 TypeScript, Lambda는 Python)
- 의미 있는 변수 및 함수 이름 사용
- 함수를 작게 유지하고 단일 책임에 집중
- 적절한 오류 처리 및 로깅 구현

## 파일 관리
- 깔끔한 디렉토리 구조 유지
- 프로젝트 전체에서 일관된 네이밍 컨벤션 사용
- 버전 관리에 임시 또는 백업 파일 포함 금지
- 기능 또는 도메인별로 코드를 논리적으로 구성
- 설정 파일을 적절한 수준에 배치 (프로젝트 vs 사용자)

## 문서화 방침
- 배포를 포함한 모든 측면을 다루는 단일 종합 README 유지
- 가능한 경우 MCP 서버를 통해 공식 소스 참조
- 의존성 업그레이드 시 문서 업데이트
- 관련 코드 가까이에 문서 배치
- 복잡한 비즈니스 로직에 인라인 주석 사용
- API 엔드포인트 및 데이터 구조 문서화
- 설정 및 배포 지침 포함

## 버전 관리 통합
- 의미 있는 메시지와 함께 자주 커밋
- 개발에 기능 브랜치 사용
- 메인 브랜치를 항상 배포 가능한 상태로 유지
- 릴리스에 적절한 태그 지정
- 생성된 파일과 시크릿을 제외하기 위해 .gitignore 사용

## 품질 보증
- 새로운 기능에 대한 테스트 작성
- 변경 사항 커밋 전 테스트 실행
- 린팅 및 포맷팅 도구를 일관되게 사용
- 모든 변경 사항에 대해 코드 리뷰 수행
- 코드 커버리지를 모니터링하고 높은 수준 유지
