# 게임 개발 모범 사례

## 게임 루프
- `requestAnimationFrame`을 사용하여 메인 게임 루프 구현
- 고정 시간 간격(fixed timestep)으로 물리 업데이트 분리
- 업데이트(로직)와 렌더링(그리기)을 명확히 분리
- 델타 타임(delta time)을 사용하여 프레임 독립적인 움직임 구현
- 게임 일시정지/재개 상태 관리 구현

## Canvas 렌더링
- 매 프레임마다 `clearRect`로 캔버스 초기화 후 다시 그리기
- 오프스크린 캔버스를 활용하여 복잡한 렌더링 최적화
- `drawImage`로 스프라이트 시트에서 개별 프레임 추출
- 캔버스 크기와 게임 해상도를 분리하여 반응형 지원
- `imageSmoothingEnabled`를 적절히 설정하여 픽셀 아트 선명도 유지

## 물리 및 충돌
- 공의 궤적에 중력, 속도, 가속도를 적용
- 네트, 바닥, 천장, 벽과의 충돌 감지를 AABB 또는 원형 충돌로 구현
- 피카츄와 공의 충돌 시 반사 벡터 계산
- 물리 상수(중력, 반발 계수 등)를 설정 객체로 분리하여 튜닝 용이하게 관리

## 입력 처리
- 키보드 이벤트(`keydown`, `keyup`)를 사용한 입력 상태 관리
- 입력 상태를 별도 객체로 관리하여 게임 로직과 분리
- 동시 키 입력(대각선 이동 등) 지원
- 터치/모바일 입력 지원 고려

## 스프라이트 및 에셋
- 스프라이트 시트를 사용하여 HTTP 요청 최소화
- 모든 에셋은 게임 시작 전 사전 로딩(preload)
- 에셋 로딩 상태를 표시하는 로딩 화면 구현
- 스프라이트 애니메이션은 프레임 인덱스와 타이밍으로 관리

## 게임 상태 관리
- 상태 머신 패턴으로 게임 흐름 관리 (메뉴, 플레이, 일시정지, 게임오버 등)
- 점수, 라운드 등 게임 데이터를 중앙 상태 객체에서 관리
- 상태 전환 시 리소스 정리(cleanup) 수행

## 성능 최적화
- 불필요한 객체 생성을 피하고 객체 풀링(object pooling) 활용
- 화면 밖 객체는 렌더링에서 제외
- `console.log`는 개발 중에만 사용하고 프로덕션에서 제거
- 가비지 컬렉션 부하를 줄이기 위해 객체 재사용

## 코드 구조
- 게임 엔진/코어와 게임 로직을 분리
- 엔티티(피카츄, 공, 네트)를 각각 독립적인 클래스/모듈로 구현
- 설정값(화면 크기, 속도, 점수 등)을 상수 파일로 분리
- 렌더러, 물리 엔진, 입력 핸들러를 모듈화
